Harness Skills & Hooks 레퍼런스

weed-harness 저장소와 로컬 ~/.claude에 설치된 skill·hook의 역할 정리

📦 저장소weedmo/skills (구 autofree) → weed-harness 플러그인 소스
🧩 리포 스킬19개 (skills/)
🖥️ 로컬 스킬9개 (~/.claude/skills/)
🪝 훅 스크립트8개 + hooks.json (hooks/)
📅 기준일2026-07-30 (OMC·weed-cowork 정리 완료 후)
💡

스킬은 3계층으로 나뉩니다. ① 이 저장소의 skills/ — weed-harness 플러그인으로 배포되는 스킬, ② ~/.claude/skills/ — 플러그인과 무관하게 로컬에 직접 설치된 스킬, ③ superpowers·ouroboros 등 다른 플러그인이 제공하는 스킬(이 문서 범위 밖).

훅은 이 저장소의 hooks/에 스크립트로 보관되고, settings.json(사용자 전역)과 hooks.json(플러그인)에 이벤트별로 등록되어 실행됩니다.

1. 리포 스킬 — weed-harness (skills/)

플러그인으로 패키징되어 /스킬명으로 호출되는 19개. 핵심은 "계획 → 팀 실행 → 리뷰 → 기록"의 개발 파이프라인입니다.

📋 계획 파이프라인

/to-prd→ /refine-plan→ /goal-set→ /team-dispatch→ /team-review
스킬분류역할
to-prd계획 현재 대화 맥락을 PRD로 합성해 프로젝트 이슈 트래커에 게시. 인터뷰 없이 바로 문서화.
refine-plan계획 Codex↔Claude 합의 루프로 plan.md를 다듬는 단계. Architect + Critic 판정을 통과할 때까지 최소 5라운드, 최대 10라운드 반복.
goal-set계획 승인된 plan.md를 goal.md(테스트 가능한 종료 조건 + 제약 + 서브팀 도구)로 압축. Codex가 실행할 목표 패키지를 만듦.
workflow-plan계획 Workflow 오케스트레이션 도구에 바로 얹을 수 있는 형태(phase / agent / parallel / pipeline / barrier 태깅)로 구현 계획을 작성.
team-split계획 마스터 플랜을 기능별 git worktree + 태스크 디렉토리(PRD/plan/goal/tools 템플릿 포함)로 분할해 병렬 작업을 준비.

🤝 팀 실행 (Codex 협업)

스킬분류역할
team-dispatch실행 goal 패키지 + 서브팀 API와 함께 기능 구현을 Codex 창(pane)에 위임. Codex가 구현자-감독자 역할을 하며 헬퍼를 스폰할 수 있음.
team-review실행 Codex 구현 결과를 goal.md 종료 조건에 대조해 리뷰하고, 소규모 리팩토링 후 /review + /ship으로 PR 생성. team-dispatch가 DONE을 남긴 뒤 사용.
team-templates실행 스킬이라기보다 템플릿 모음 — team-split이 사용하는 prd.md / plan.md / goal.md / tools.md 원본.

🔁 자율 루프

스킬분류역할
autocode루프 자율 코드 개선 루프. 단일 에이전트 모드(순차 실험 + PIVOT/REFINE 판단)와 PGE(Plan-Generate-Execute) 팀 모드 지원. 서브커맨드: install / init / run / status / resume.
auto_research루프 ML 연구용 자율 실험 루프. 딥 인터뷰로 초기화하고, 선택적으로 23단계 연구 파이프라인(AutoResearchClaw) 실행. 문헌 검색·멀티에이전트 토론·품질 게이트 포함.

📝 기록 · 배포 · 유지관리

스킬분류역할
devlog기록 개발 로그 허브 — /devlog(개발 저널), /devlog tsg(트러블슈팅 가이드), /devlog search(통합 검색)로 logs/ 하위 기록을 관리. 아래 devlog-hook이 커밋마다 자동 트리거.
deploy-verify배포 배포 후 검증 파이프라인: PR 머지 → 카나리 모니터링 → 벤치마크를 체인으로 실행. /deploy-verify canary는 모니터링만.
harness-sync유지관리 로컬 ~/.claude/ 설정(hooks, skills, CLAUDE.md, settings.json 등)을 이 저장소로 동기화하고 버전 패치범프 → 커밋 → 태그 → 푸시 → GitHub Release → 플러그인 캐시 갱신까지 수행. "sync"라고 말하면 실행.
setup유지관리 새 환경에 weed-harness를 셋업 — statusLine HUD, Codex 플러그인 연결, 커스텀 훅 등록 등. 멱등이라 반복 실행해도 안전.
skill-subscribe유지관리 외부 GitHub 저장소에서 스킬 하나만 골라 ~/.claude/skills에 설치하고 업스트림과 동기화 유지. SessionStart 훅(check.py)이 업데이트를 알림.
find-skills유지관리 "X를 하는 스킬 있나?" 같은 질문에 설치 가능한 스킬을 탐색·설치하도록 도움.
context-budget유틸 에이전트·스킬·MCP·룰이 컨텍스트 윈도우를 얼마나 소비하는지 감사. 상시 로드 vs 온디맨드 오버헤드를 구분해 토큰 예산 산정.
merge-resolve유틸 머지 충돌 발생 시 충돌 헝크를 하나씩 보여주며 사용자가 해결안을 고르게 하는 대화형 해결 가이드. merge-conflict-trigger 훅이 자동 호출.
type-graph유틸 Python 코드베이스의 함수 단위 타입·호출 그래프 생성 (ROS rqt_graph 스타일).

2. 로컬 스킬 (~/.claude/skills/)

플러그인 배포와 무관하게 직접 설치된 9개. 출처별로 gstack 계열 / Orca 계열 / 독립 스킬로 나뉩니다.

스킬출처역할
browsegstack QA 테스트·사이트 도그푸딩용 고속 헤드리스 브라우저.
qagstack 웹 애플리케이션을 체계적으로 QA 테스트하고 발견된 버그를 수정.
scrapegstack 웹 페이지에서 데이터 추출.
diagramgstack 영어 설명(또는 mermaid 소스)을 다이어그램 3종 세트로 변환 — 소스 + 편집 가능한 .excalidraw 파일 포함.
orca-cliOrca orca CLI로 Orca가 관리하는 worktree·터미널·자동화·내장 브라우저를 조작. 다른 에이전트로의 완전한 핸드오프(handover)에도 사용.
orchestrationOrca Orca 멀티에이전트 조율 — 스레드 메시지, ask/reply 블로킹 플로우, 태스크 DAG, 의사결정 게이트, 코디네이터 루프.
computer-useOrca Orca의 computer-use CLI로 로컬 데스크톱 앱 창을 접근성 트리·스크린샷·안전한 UI 액션으로 검사·조작.
graphify독립 모든 입력(코드·문서·논문·이미지)을 영속 지식 그래프로 변환. graphify-out/이 있으면 코드베이스 질문을 그래프 쿼리로 먼저 처리해 토큰 절약. pip 패키지 graphifyy로 배포.
karpathy-guidelines독립 LLM 코딩 실수를 줄이는 행동 지침 — 과잉 설계 방지, 수술적 변경, 가정 표면화, 검증 가능한 성공 기준. 모든 코드 작업에서 호출하도록 CLAUDE.md에 명시.

3. Hooks (hooks/)

이벤트에 자동 반응하는 스크립트 8개. OMC 관련 훅(omc-skill-filter)은 정리 완료로 삭제됐습니다.

훅이벤트역할
codex-task-review.shSubagentStop 서브에이전트 작업이 끝나면 백그라운드에서 codex exec --full-auto로 diff를 리뷰·자동수정. ALLOW/FIXED면 태스크당 1커밋 자동 생성, BLOCKED면 메인 세션에 해결 요청 (asyncRewake로 재기동).
devlog-hook.shPostToolUse: Bash git commit 성공을 감지해 자동 분기: fix/bug 커밋 → TSG 기록, revert 커밋 → devlog reject, 일반 커밋 → devlog 기록, devlog/TSG 문서 커밋 → 자동 PR 체인.
tsg-bash-failure.shPostToolUse: Bash 명령이 실패(exit ≠ 0)하면 기존 TSG에서 해결책을 검색하거나 미해결 이슈로 기록하라고 제안.
merge-conflict-trigger.shPostToolUse: Bash git 머지 출력에서 CONFLICT를 감지하면 merge-resolve 스킬을 트리거하는 매직 키워드를 출력.
gstack-skill-filter.shPostToolUse gstack 업데이트 후 allowlist(browse, qa 등) 밖의 gstack 스킬을 비활성화해 스킬 목록 오염 방지.
graphify-claudemd-inject.shPostToolUse: Skill /graphify 스킬 실행 후 프로젝트 CLAUDE.md에 graphify 운용 섹션을 자동 주입.
graphify-upgrade-check.shSessionStart PyPI의 graphifyy 최신 버전과 pipx 설치 버전을 비교해 뒤처지면 한 줄 알림. 자동 적용은 하지 않으며, 실패해도 세션 시작을 막지 않음.
language-rule.shUserPromptSubmit 매 프롬프트마다 언어 규칙 리마인더 주입 — 사용자 보고/대화는 한국어, 코드·주석·커밋 메시지는 English.
hooks.json플러그인 등록 weed-harness 플러그인이 설치될 때 등록되는 훅 선언. 현재는 SubagentStop → codex-task-review.sh 하나만 남음 (OMC 필터 제거됨).
실제 등록 위치 — settings.json vs hooks.json

같은 스크립트라도 어디에 등록되느냐에 따라 적용 범위가 다릅니다.

  • settings.json (사용자 전역) — 모든 세션에 적용:
    • SubagentStop codex-task-review.sh (timeout 600s, asyncRewake)
    • UserPromptSubmit language-rule.sh
    • SessionStart skill-subscribe/scripts/check.py --hook (업스트림 스킬 업데이트 확인) + graphify-upgrade-check.sh
  • hooks.json (플러그인) — weed-harness 플러그인이 활성화된 경우에만: SubagentStop → codex-task-review.sh (timeout 900s)
  • 나머지 훅(devlog, tsg, merge-conflict, gstack-filter, graphify-inject)은 /setup 스킬이 사용자 설정에 등록해 주는 방식입니다.

참고: 리포의 settings.json은 업스트림에서 vendored된 파일이라 /home/weed/ 경로가 남아 있습니다 — 로컬 설정 원본이 아닙니다.

🔄

훅이 만드는 자동화 루프. 커밋하면 devlog-hook이 기록을 남기고, 명령이 실패하면 tsg-bash-failure가 과거 해결책을 찾아주며, 서브에이전트가 일을 마치면 codex-task-review가 리뷰·수정·커밋까지 처리합니다. 세션이 시작될 때마다 skill-subscribe와 graphify 업데이트 확인이 돌아 하니스가 스스로 최신 상태를 유지합니다.
